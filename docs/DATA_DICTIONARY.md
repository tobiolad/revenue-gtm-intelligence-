# Data dictionary

All data in this project is synthetic, generated by `generator/generate.py`
with a fixed seed (`SEED = 19` in `generator/constants.py`). Nothing here
is real CRM, customer, or sales data. Tables below are as created by
`db/sql/001_schema.sql`.

### `opportunities`

One row per deal, Open or Closed.

| Column | Notes |
|---|---|
| `opp_id` | PK |
| `account_id`, `owner_id` | FKs to `accounts` / `sales_reps` |
| `lead_source` | One of Outbound / Inbound / Referral / Partner / Event; nullable (~2% of deals have no recorded source -- a CRM data-entry gap). **Drives win rate** -- see below |
| `amount` | Deal value |
| `created_date` | |
| `expected_close_date` | The rep's own target close date, **set at creation and independent of the actual outcome** -- this is the field the forecast buckets open deals by month on |
| `status` | `Open` \| `Closed` |
| `stage` | Current stage if Open, final stage if Closed: Prospecting / Qualification / Proposal / Negotiation / Closed Won / Closed Lost |
| `forecast_category` | Derived from `stage`: Pipeline (Prospecting, Qualification) / Best Case (Proposal) / Commit (Negotiation) / Closed Won / Closed Lost |
| `closed_date` | Nullable: only set once `status = 'Closed'` |
| `lost_reason` | Nullable: only set when `stage = 'Closed Lost'`. One of Budget / Competitor / No Decision / Timing / Price |

### `stage_history`

Event-sourced: one row per (opportunity, pipeline stage actually reached),
in order. `opportunities.stage` is a convenience column for simple
lookups; every funnel, conversion, and forecast-calibration query reads
`stage_history` (via the `stage_progress` view) instead -- the same
discipline as `onboarding_progress` in the companion Product Analytics Lab
project.

| Column | Notes |
|---|---|
| `opp_id` | FK to `opportunities` |

| `entered_at` | Timestamp the opportunity entered this stage |

## The pipeline model

Every opportunity moves through a **strictly sequential funnel**:
Prospecting → Qualification → Proposal → Negotiation → Closed Won, with
the possibility of being marked Closed Lost at the end of any stage
instead of advancing. This means **winning is only possible by advancing
out of Negotiation** -- a fact that matters directly for how the forecast
weights are computed (see `docs/FORECAST_METHODOLOGY.md`): a naive "win
rate of deals whose final stage was X" is 0% for every stage except
Negotiation by construction, which is why the forecast instead uses "win
rate of deals that ever *reached* stage X."

## What drives win rate (the generator's ground truth)

- **Lead source quality** (`LEAD_SOURCE_QUALITY` in `generator/constants.py`)
  multiplies every stage-advance probability. Referral leads convert far
  better than Outbound by design -- the Pipeline Funnel page's "win rate
  by lead source" table exists to recover this ranking from the data, not
  assert it.
- **Deal creation volume ramps up** over the data window (a growing GTM
  org), not uniform -- see `sample_created_date` in `generator/generate.py`.

## Known limitations (intentional, not bugs)

- ~2% of deals have no recorded `lead_source` (shown as "Unknown" in the
  dashboard, never silently dropped from denominators).
- `expected_close_date` is a genuine estimate made at deal-creation time,
  independent of what actually happens -- it is often wrong, the same way
  a real rep's target close date is. This is what makes the forecast
  backtest in `docs/FORECAST_METHODOLOGY.md` meaningful rather than
  circular.
